The [Master PRD](../reference/JanSahabhag_2047_MASTER_PRD_v3.1_LOSSLESS_ARCHIVE.docx) governs the product, the [reservation supplement](../reference/JanSahabhag_2047_Supplementary_PRD_33pct_Womens_Reservation_v2.docx) supplies the approved-in-principle policy, [decisions](../decisions.md) records owner choices, and the [package plan](COMPETITION_DEMO_PRD_PLAN.md) holds detailed acceptance criteria. This brief does not redefine those sources.

- **Substantial demo feature work:** assignment/evidence (03), the full Youth Assembly procedure (05), Workspace (06), Passport/Credits cross-record truthfulness (07), reservation examples and validation (08), and the five-minute acceptance journey (09). These are six feature/acceptance packages, not six small fixes.

## Ordered tasks for the current demo

1. **Integrate the accepted work and establish one baseline.** The owner merges the Phase 0 inventory and audit, five-stage method, latest navigation/UHV/Debate Room chain (`agy/j-20261014-114143-73o2`), and the phone repair (`agy/j-20261012-215520-ssz8`). The latest Debate Room branch supersedes earlier navigation, UHV and Debate Room branches in that chain. Resolve overlapping browser-test changes; run `npm run build`, `npm run test:run`, `npm run test:e2e`, and inspect 320px, 375px and desktop layouts. The independently passing 141 unit and 14 browser tests do not prove that merged combination.
2. **Finish Phase 0 certification (00).** Reconcile the old 47-route inventory with the added routes and all controls. For each meaningful route/control, record Keep/Change/Build/Remove/Not Verified, current functionality, demo label, desktop/mobile behavior, and a link to evidence. Check reload, reset, broken record, denied action and browser storage behavior. Repeat an interactive sample on the deployed URL after publication; the earlier deployed check covered only four representative routes visually.
3. **Build the assignment-to-evidence leg (03).** Make the Jaipur assignment recoverable through save/resume; record a distinct observation, evidence metadata or an actual upload with its true status, receipt and time. Model pending/rejected/accepted review without letting a self-submitted item appear independently verified. Test interruption, retry, correction and the route into deliberation. If file ingestion is not implemented, label it as demo metadata.
4. **Complete the local session/rulebook path (04).** Check that the Debate Room's motion, queue, facilitator action, text intervention, rule acknowledgment and Debate-to-Assembly transition preserve only authorized context. Add missing fallback, phase and denied-action cases found by the combined audit. Clearly label the local simulation. Live video/recording and true shared participation require separate decisions and server work.
5. **Replace the Youth Assembly procedure (05).** Implement four non-hierarchical zones—Thinker, Enabler, Troubleshooter, Shaper—and the six canonical stages: Frame, Think, Enable, Troubleshoot, Shape, Final Assembly. Give the Chair only the documented procedural powers. Support the specified response and outcome states, three-person mini-deliberation and proposition revisions while retaining dissent. Test unauthorized stage changes and revision history on desktop/mobile.
6. **Build Workspace around the proposition (06).** Provide a fictional username invitation, accept/decline, scoped membership, moderation action and audit trail in the same Jaipur story. Start with private or institution-scoped discovery; show the relevant rulebook where action occurs. Test non-member and moderator-denied actions, removal, refresh and recovery. Describe it as one-browser simulation, not a shared service.
7. **Make Passport and Credits traceable (07).** From the same participant journey, link assignment, evidence/review state, session/Assembly contribution, dissent and reflection to Passport entries. Explain credit source and allow correction where a review/status can change. Keep private UHV and Debate journals out of civic credentials. Test that pending or self-asserted evidence never displays as verified or earns a verification-only reward.
8. **Apply the reservation policy to applicable demo allocations (08).** Show fictional, labelled allocations and use `ceil(0.33 × applicable allocated places)` separately for each allocation. Do not pool places; leave unfilled reserved places vacant. Recalculate on size/selection change, block a noncompliant finalisation, and expose aggregate compliance without disclosing an individual's declaration. Decide the Assembly role and limited-event boundaries (OD.19) and the exception rule (OD.17) before fixing those exact flows; do not silently invent an exception. The browser demo cannot claim server enforcement or real-data compliance.
9. **Run the complete Jaipur story and publish only the accepted build (09).** Demonstrate Learn → Observe → Deliberate → Propose → Reflect within about five minutes, including assignment, evidence status, Debate/Assembly, dissent, Workspace invitation and Passport. Exercise reset, refresh, low-bandwidth text path, keyboard and phone use, and a failed/denied path. Update truthful demo/prototype labels. After the owner accepts the combined build, push the intended branch and deploy it to Vercel; inspect the deployed version rather than relying on a build command alone.
