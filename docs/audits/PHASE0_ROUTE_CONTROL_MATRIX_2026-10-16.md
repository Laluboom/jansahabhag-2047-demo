## 1. Executive Summary & Verification Boundary

This document completes the static and source-evidence portion of the **Master PRD Phase 0 route and control audit** for JanSahabhag 2047 on the final fictional Jaipur demonstration branch.

### 1.1 Core Audit Scope & Governing Baseline
The Master PRD opening §2 and §A2 mandate an exhaustive pre-implementation site and repository inventory to classify all screens and controls into **Keep**, **Change**, **Build**, **Remove**, or **Not Verified** before production freeze. This inventory verifies the actual codebase of the final Jaipur branch, reconciling current code against the canonical eleven-item learner navigation, 6-stage Youth Assembly deliberation, text-first Debate Room, private invite-only Workspace, isolated UHV / Jeevan Vidya stream, 33% women's reservation allocation checks, and evidence-backed Civic Passport.

### 1.2 Verification Tier Distinction
To maintain audit integrity and avoid inferring runtime correctness from static declarations, all findings explicitly distinguish four evidence tiers:
1. **Source-Inspected:** The component, data dependency, and state bindings were directly examined in repository code.
2. **Local Browser-Observed (Automated Playwright E2E):** The page was loaded in a headless Chromium instance under Playwright test runners (`e2e/`), asserting specific DOM nodes, interactive mutations, reload persistence, or error states.
3. **Deployed Sample Observed (12 October 2026):** Four routes (`/dashboard`, `/assemblies/.../session`, `/parliament`, `/admin/dashboard`) were inspected on the live Vercel deployment (`https://jansahabhag2027.vercel.app`) using its visible accessibility tree on historical baseline `c4e0861`. Current public deployment status has not been retrieved in this task.
4. **Not Verified:** Any route, visible button, tab, filter, modal trigger, or interactive control that has not been exercised and validated in an actual browser execution. A router entry or passing test file name is **not** evidence that all controls function.

### 1.3 Disclaimer on Server Authority and Launch Readiness
> [!IMPORTANT]
> **No Claim of Production Readiness or Server Authority:**
> The current codebase is an interactive single-browser React/Vite demonstration using client-side `localStorage`. It contains **no production backend, no server-side identity or RBAC enforcement, no multi-device synchronization, and no real external municipal/video APIs**. Passing tests (311 unit tests across 24 test files, 12 Playwright suites) demonstrate client simulation invariants only. This audit does **not** certify public launch readiness, server-side data durability, or compliance with statutory child-safeguarding/privacy laws.

## 3. Platform Infrastructure & System Invariants Inventory

### 3.1 Authentication & Persona Simulation
- **Mechanism:** Implemented via Zustand store ([src/stores/authStore.ts](../../src/stores/authStore.ts)) backed by [src/services/demoRepository.ts](../../src/services/demoRepository.ts).
- **Available Personas:** 7 primary selectable personas in [DemoLoginPage.tsx](../../src/features/auth-demo/DemoLoginPage.tsx) representing core roles:
  1. `user_aarav` (Aarav Sharma — Youth Participant, Student at Navchetna Public School)
  2. `user_meera` (Meera Singh — Youth Participant / Dissent Advocate)
  3. `user_kavita` (Kavita Rao — Teacher / Mentor, Assignment Reviewer)
  4. `user_rohan` (Rohan Mehta — Assembly Facilitator / Chair)
  5. `user_ananya` (Ananya Verma — Institution Admin)
  6. `user_dev` (Dev Patel — Programme Manager / State Mission Lead)
  7. `user_admin` (Demo Administrator — Platform Owner / Policy Lead)
- **Security Limitation:** Authentication is simulated entirely on the client. Switching personas writes `activeUserId` to browser storage without password, session cookie, or cryptographic bearer token.
- **Absence of Route Guards:** [src/app/router.tsx](../../src/app/router.tsx) contains no router-level permission guards or redirect middleware. Any persona or unauthenticated client directly accessing `/admin/dashboard` or `/institution/dashboard` will render the administrative view. The app relies on an informative disclaimer banner (`Simulated Session Role: Platform Admin (...)`) rather than an authorization wall.

### 3.2 Browser Storage & Local Persistence
- **Storage Driver:** [src/services/persistence.ts](../../src/services/persistence.ts) persists database state to `window.localStorage` under the single key `jansahbhag_demo_v1`.
- **Seed Payload & Migrations:** Initial seed is ~264 KB containing courses, assignments, assemblies, debates, workspaces, notifications, and reservation declarations. Schema migrations are handled in [src/services/migrations.ts](../../src/services/migrations.ts) (currently at schema version 2).
- **In-Memory Fallback:** When `localStorage` is disabled or quota is exceeded, `PersistenceService` falls back to `inMemoryDatabase`.
- **State Synchronization:** Local mutations notify reactive UI components through `useAppRefreshStore` ([src/stores/useAppRefreshStore.ts](../../src/stores/useAppRefreshStore.ts)).
- **Divergence from PRD:** All data is confined to a single browser profile. There is zero server durability, no multi-device persistence, and no cross-user real-time state synchronization.

### 3.3 API & Backend Absence
- **Endpoint Reality:** There are **zero HTTP REST endpoints and zero GraphQL/WebSocket servers**.
- **Service Layer:** All operations execute within browser memory via asynchronous Promise mocks in [src/services/demoRepository.ts](../../src/services/demoRepository.ts) and [src/services/reservationAllocationService.ts](../../src/services/reservationAllocationService.ts).
- **Latency Emulation:** Synthetic delays (`setTimeout(..., 50)`) emulate asynchronous network behavior.

### 3.4 External Integrations Status
- **Live Video / Audio:** PRD OD.4 specifies video with text/audio fallback. The codebase implements an accessible **text-first chamber** with a clearly rendered `Text-First Active (OD.4) — Preview` badge ([src/components/layout/DebateRoomPreviewPage.tsx](../../src/components/layout/DebateRoomPreviewPage.tsx#L157)). No WebRTC, LiveKit, or Agora media servers are connected.
- **GIS & Mapping:** Issue locations record coordinate metadata ([src/data/seed/issues.ts](../../src/data/seed/issues.ts)), but no interactive Leaflet, Mapbox, or GIS server is connected.
- **AI Services:** Role-aware AI assistance (PRD §A16) is simulated locally with deterministic client-generated suggestions; no OpenAI, Gemini, or Anthropic API keys or external inference endpoints are integrated.
- **Municipal Stakeholder Routing:** Simulated via clickable preview cards on `/stakeholders` ([src/features/previews/StakeholdersPage.tsx](../../src/features/previews/StakeholdersPage.tsx)). No government grievance portal or municipal ticket router is wired.

### 3.5 Deployment Path & Environment
- **Toolchain:** Built with Vite 5.4.9, React 18.3.1, TypeScript 5.6.3, and Tailwind CSS 3.4.14.
- **Routing Engine:** React Router 6.27.0 with client-side HTML5 pushState history (`createBrowserRouter`).
- **Production Host:** Deployed as a static client application on Vercel (`https://jansahabhag2027.vercel.app`).
- **Deployment Divergence & Limits:** The 12 October live observation of `https://jansahabhag2027.vercel.app` reflected historical baseline `c4e0861`. Current public Vercel deployment status has not been retrieved in this task; Packages 01–09 (canonical 11 learner navigation items, 6-stage assembly, debate room simulation, private workspace, 33% reservation allocation, and connected Jaipur journey) are verified locally on this branch and are not known to be deployed.
